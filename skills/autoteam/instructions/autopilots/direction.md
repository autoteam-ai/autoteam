出一份月度方向报告，写在本任务的评论里，然后把本任务设为 done。分「前沿扫描」和「路线图对账」两节；某节没有值得改的，就写「本节无需调整」。你只出报告，不建任务、不改代码。

## 1. 前沿扫描

这套流程的指令、参数和项目设计是在某个时间点定的；外部前提、AI 工程实践和技术栈持续变化，对照仓库找出值得调整的地方。最多列 5 条发现，按对本项目的影响排序：

- A. 流程前提：registry.yaml 里每个 agent CLI 的当前版本、默认模型、上下文窗口和价格，和机器上装的版本对比；accounts 段写的额度窗口和上限还对不对；Multica 的状态、唤醒、autopilot 行为；GitHub 的规则集、合并队列、App 权限。
- B. AI 工程实践：agent 协作模式、上下文和记忆管理、自动评审和测试方法、skills/MCP/工具协议的新做法，对照角色指令、autopilot 和脚本，判断哪些设计可以改进或已过时。
- C. 项目技术栈方向：先从 `package.json`、`Dockerfile`、CI 配置和 `AGENTS.md` 识别实际技术栈，再查主要语言、框架、运行时、基础设施的新大版本、弃用或 EOL 计划、社区主流替代。

每条发现都附来源链接和来源日期，查不到就写「查不到」，不要猜；没有联网检索能力时，至少查本地版本号和已装的 changelog，并写明只查了哪些。每条保留三段：变了什么；因此现在哪里不适配，具体到 `<文件>:<行>` 或某个 `AUTOTEAM_*` 参数；建议怎么改。B、C 类另加「时机」：**现在改**、**下个版本前改**或**持续观察**（写明触发条件，不要求 Planner 建任务）。平台新增了能把现在只靠指令约束的一条变成硬约束的能力，优先报，对照 `docs/concepts/invariants.md` 的四条不变量看。

## 2. 路线图对账

1. 读 README、AGENTS.md 和 docs 里的目标或路线图，列出还没做的部分，和现有任务（backlog、todo、进行中）查重，缺的部分写成独立的小任务建议。
2. 项目有 docs/concepts/invariants.md 时做不变量对账：以「已知的偏离」表为依据，逐条检查四条不变量的“怎么验证”还成不成立，以及最近合并的改动有没有产生表里没登记的偏离；说明破坏的是哪一条。

最后按 Auditor 角色指令提及 Planner 一次；缺口由 Planner 拆进 backlog，并按「放行分级」处理。
