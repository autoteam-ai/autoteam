# 写 AGENTS.md

AGENTS.md 是每个 agent 每次运行都会读的常驻上下文。写多了不仅烧 token，还会让成功率下降：ETH Zurich 2026 年的实验里，LLM 生成的上下文文件让任务成功率降了 3%，人写的也只提升 4%，推理成本却增加 20% 以上。

## 只写两类规则

1. **从代码里看不出来的**：为什么这么设计、哪些是历史包袱、哪些看起来能复用其实不能；
2. **容易搞错的**：模型的“常识”和本项目约定相反的地方。

能用类型、lint、依赖检查表达的约束，放进 `make check`，不写进 AGENTS.md。

## 写法

- 禁止项要带原因，最好再给替代做法：“不要 X，因为 Y，改做 Z”。模型跟随“为什么”比跟随“不要”好得多。
  - 差：`路由处理器里不要用 try-catch。`
  - 好：`路由处理器里不要用 try-catch：错误统一交给全局中间件，才能集中记日志、返回一致的错误响应。`
- 内部从严、边界从宽要写清楚：内部代码不要加兼容层；但服务端返回的数据要校验、enum 要有 default 分支。
- 临时绕路的代码显式标成债务，防止 agent 把权宜之计当范式到处复制。
- 分层：根目录放全局规则，子目录（子包、子服务）放各自的 AGENTS.md，离文件最近的优先。

## 篇幅

常驻上下文（根 AGENTS.md 加全局规则）控制在模型有效上下文的 5% 以内，200K 的模型大约 1 万 token。其余放进按需加载的文档或 skill。

定期做噪声测试：删掉一段你怀疑冗余的内容，跑同样的任务，agent 行为没变化，那段就是在烧 token。

## ai-workflow 的受管块

`aiwf init` 会在 AGENTS.md 末尾追加一个受管块（`<!-- >>> ai-workflow >>> -->` 之间），只有四条：怎么跑检查、不谎报验证、PR 标题规则、哪些是规则文件。不要改受管块里的内容，要改就改 ai-workflow 的模板。
